# iPhone 15 검증 및 재방문 테스트

현재 상태: iOS 프로젝트 생성 및 웹 코드 연결 완료. Xcode 전체 앱이 없는 개발 Mac에서 네이티브 컴파일/서명/실기기 실행은 하지 않았다. WebKit 자동화는 iPhone 15 화면/터치 환경 에뮬레이션이며 실제 iOS 검증을 대체하지 않는다.

## iOS 빌드

- Node 22 이상, Xcode 26 이상을 설치한다.
- `npm ci` 후 `npm run ios:sync`, `npm run ios:open`.
- Xcode에서 자신의 Signing Team과 고유한 Bundle ID를 확인한다. 현재 ID `com.djkdb.zunran`은 등록/소유 확인 전 개발용이다.
- iPhone 15를 연결하고 신뢰/개발자 모드를 설정한 뒤 Run 한다.
- 게임 에셋은 앱에 내장되고 서비스워커는 네이티브에서 등록하지 않는다. 기록/진행 중인 판/동의한 테스트 기록은 Capacitor Preferences에 저장된다. 웹/PWA는 localStorage를 사용하며 두 저장소는 자동으로 이전되지 않는다.
- 앱 랭킹을 사용하려면 `VITE_API_BASE=https://실제-랭킹-서버 npm run ios:sync`로 빌드한다. 서버에 이 변경의 rank middleware도 배포해야 한다. 미지정 시 랭킹은 서버 미연결로 표시되며 외부 서버로 요청하지 않는다.
- 개인정보 manifest에는 Preferences 사용 이유를 포함했다. 공개 배포 전 실제 서버 데이터 처리에 맞춘 개인정보처리방침/스토어 개인정보 공개/서명/연령 등급 확인이 별도로 필요하다.

## 실기기 체크 (아직 미실행)

1. 세로에서 시작·소환·합성·드래그·탭 이동. 가로 전환 후 동일 조작, 노치/홈 인디케이터 겹침 확인.
2. 10초 이상 플레이 후 홈으로 이동. 다시 열면 멈춘 상태이며 코인/유닛/웨이브가 그대로인지 확인.
3. 앱 전환기에서 종료 후 재실행 → ‘이전 근무 이어하기’. 정지 해제 전 전투가 진행되지 않아야 한다.
4. 보상/사건/승급 선택 화면에서 종료 후 이어하기. 선택을 다시 해야 하며 보상이 중복 적용되지 않아야 한다.
5. 비행기 모드에서 앱을 강제 종료하고 재실행. 게임은 동작하고 랭킹 연결 실패가 플레이를 막지 않아야 한다.
6. 근무 종료 후 재실행. 수당/플레이 횟수가 한 번만 증가해야 한다.
7. 20분 이상 플레이하며 발열·배터리·끊김·사운드 복귀를 기록. 전화/알림/화면 잠금 후에도 확인.

체크포인트는 성공한 수동 조작 직후, 5초 간격, 백그라운드 전환 시 저장한다. 갑작스러운 종료는 마지막 완료된 쓰기 이후 진행을 잃을 수 있다. 백그라운드 저장을 OS가 항상 완료한다고 보장하지 않는다. 기존 누적 기록을 보존하며 손상된 체크포인트는 이어하기에서 제외한다.

## Safari로 먼저 확인할 경우

같은 Wi-Fi의 Mac에서 `npm run preview -- --host 0.0.0.0 --port 4197` 후 Mac의 LAN 주소를 Safari로 연다. HTTP LAN 테스트는 조작/복구 확인용이며 서비스워커 오프라인 설치 테스트용이 아니다. 홈 화면 PWA 및 오프라인 테스트에는 HTTPS로 배포된 동일 빌드를 사용한다. 기존 공개 사이트는 이 브랜치 배포 전까지 이전 버전이다.

## 실제 사람의 재방문

- 20~30명 모집은 아직 하지 않았다. 자동 테스트 결과를 사람 결과에 섞지 않는다.
- 설정 → 플레이 테스트 참여 → 동의. 기본 꺼짐, 서버 자동 전송 없음. 닉네임·연락처·광고 식별자는 수집하지 않는다.
- 첫날 자유롭게 플레이한다. 다음 날 다시 하도록 알림/독촉하지 않아야 자발적 재방문을 볼 수 있다.
- D1: 첫 10초 이상 플레이가 기록된 시각부터 24~48시간 사이에 다시 10초 이상 플레이. D7: 168~192시간. 같은 날 두 번째 판 시작은 별도 지표다.
- D1 관찰이 끝난 48시간 이후(그리고 D7은 192시간 이후) 설정 → 테스트 기록 보기·복사를 눌러 자발적으로 전달받는다. 개인정보 안내 후 담당자가 파일로 보관한다.
- `node scripts/summarize-study.mjs /path/to/report1.json ...`으로 집계. 같은 기기의 중복 제출은 최신 한 개만 사용한다. 제출 후 시간은 관찰된 것으로 취급하지 않는다.
- 로컬 기록/자발적 제출 방식은 미제출자를 볼 수 없다. 전체 모집자의 D1 유지율로 보고하지 말고 모집 인원·제출 인원·관찰 완료 인원을 함께 표기한다. 기기 삭제·재설치는 새 표본이 될 수 있다.
- 참여 해제 시 해당 테스트 기록을 삭제한다. 재가입은 새 표본이다. 실제 테스트 결과는 아직 없다.

## 자동 검증

- `npm test`, `npm run typecheck`, `npm run ios:sync`.
- `npx playwright install webkit` 후 `npm run test:resume` (빌드된 dist를 임시 서버로 제공, 서버 종료로 네트워크 장애를 재현).
- `CHROME_PATH=/path/to/chrome npm run test:controls` (preview 4196 실행 필요).
- 참고: Playwright WebKit의 `setOffline`은 이 환경에서 서비스워커까지 차단하므로 테스트는 원본 HTTP 서버를 실제로 종료해 캐시 복구를 검사한다.
